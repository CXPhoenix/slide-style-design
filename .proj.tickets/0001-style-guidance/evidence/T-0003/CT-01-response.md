## 比爾蓋茲流核心指引

本次採用 **Bill Gates-inspired analytical style**，核心規則為 `gates.evidence_relation`。

現場投影時，重點不是追求資訊密度，而是讓觀眾能快速看懂「**這份證據到底支持哪個比較或系統判斷**」。圖表、數字、流程圖與系統元件都應連到一個明確陳述的分析重點，避免只有醒目的數字，卻不知道它代表什麼。

對投影環境，建議以清楚的視覺層級呈現：先讓分析結論或比較關係成為主要視覺焦點，再讓圖表、數量或系統元件作為支撐證據。可用箭頭、括號、局部標註、基準線、差值或簡短註解指出「哪兩者在比較」、「哪個數值支持哪個判斷」或「哪些系統元件彼此產生影響」。

可以使用較大的留白、較少的裝飾與較清楚的區塊分隔；**高密度不是比爾蓋茲流的必要條件**。對現場投影而言，若降低裝飾能讓證據關係更容易被看見，反而更符合此風格。

若既有資料中的 **指標名稱、單位、基準、測試條件、假設、樣本範圍或適用限制** 對正確解讀有必要，就必須保留。不能為了字變大、畫面變乾淨或投影更簡潔，而把這些資訊拿掉。例如「延遲 120」不足以解讀；若原始證據是「平均 API response latency：120 ms，16 concurrent users」，就應維持單位與必要測試條件之間的關係。

比較型內容尤其要避免孤立數字。視覺上應讓觀眾知道比較基準，例如 A 與 B 使用相同工作負載、不同架構，或某項數值相較基準增加／下降多少。數字大小只是視覺層級工具，不能取代比較關係本身。

系統架構型內容則應明確呈現元件之間的關係。元件名稱、資料流向、控制關係或因果鏈應服務於一個明確的系統觀點，而不是單純排列大量方塊。若某條連線或元件是分析結論的關鍵，可以提高視覺權重或加入簡短註解。

這套規則是根據 Gates 的分析取向與公開演講材料所做的專案式綜整，並不是 Bill Gates 本人提出的正式簡報方法，也不意味著必須把所有資訊塞在同一頁、使用大量圖表，或禁止故事與幽默。

```yaml
style_id: gates
core_rules:
  - rule_id: gates.evidence_relation
    constraint: >-
      讓證據、數量或系統元件連到明確陳述的比較或系統重點，使現場觀眾能辨識
      證據支持什麼、數量正在比較什麼，以及系統元件如何彼此關聯。使用清楚的
      視覺層級、空間配置與必要註記強化這些關係。若指標名稱、單位、比較基準、
      假設、測試條件、適用範圍或其他限定對正確解讀既有證據是必要的，必須保留
      它們與證據之間的關係，不得為了投影簡潔、字級放大或增加留白而刪除。
      可使用較多留白、較少裝飾與較明確的重點層級；高資訊密度不是必要條件，
      孤立數字或沒有明確分析關係的圖表不符合核心要求。
adjustable_rules: []
```
